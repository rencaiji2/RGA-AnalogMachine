# Agent Notes

## Build

- Qt Widgets desktop app built with `qmake`.
- Project file: `RGA-AnalogMachine.pro`.
- Required Qt modules: `core`, `gui`, `widgets`, `network`.
- C++ standard: `c++11`.
- Typical build flow:
  ```bash
  qmake RGA-AnalogMachine.pro
  make          # or nmake / jom on Windows
  ```
- `RGA-AnalogMachine.pro.user` is Qt Creator user state — do not commit or hand-edit.

## Entry Point & Architecture

- Entry point: `main.cpp` → `Widget`.
- `Widget` owns two `TcpServer` instances (`m_tcpServer` and `m_tcpServer_2`).
- Servers listen on hard-coded loopback ports:
  - `m_tcpServer`: `127.0.0.1:6000`
  - `m_tcpServer_2`: `127.0.0.1:6001`
- `TcpServer` subclasses `QTcpServer`; per-client handling lives in `ClientSocket` (`QTcpSocket` subclass).
- UI form is defined in `widget.ui`; implementation uses `ui_widget.h` generated by `uic`.

## Protocol / Data

- `AgreementZXJC` in `PublicStruct.h` defines a fixed-position, comma-separated protocol string (simulating the "Nanyang" / ZXJC protocol).
- `Widget::initTcpData_1()` and `handleUiSetting()` map UI checkboxes to specific indices in that payload.
- The periodic `m_sendTimer` currently sends little (mostly commented out); `m_testTimer` emits a hard-coded `SV,...` heartbeat on port 6001.

## Testing / CI

- No test suite, no CI workflows, no lint/typecheck tooling present.
- Verify by building and running the GUI; confirm both TCP servers start without port conflicts.
